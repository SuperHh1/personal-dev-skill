# 协助分析（16 项能力 · 判据与输出格式）

> **⚠️ 头一条铁律**：本文件所有能力都只做「**协助分析**」——
> 输出永远是「**选项 ＋ 后果 ＋ 推荐**」，⛔ **绝不替人拍板**（`SKILL.md` E1）。
> **所有选型一律照 `选型横评模板.md`，以实测为主**（L1/L2/L3）。

---

## 通用输出格式（16 项都用这个壳）

```
【结论】一句话（人话）
【依据】每条后面跟出处：实测 / 文件:行号 / URL / ⏳未实测
【选项对比】表格（选项 × 维度）
【推荐】X，理由… ；⚠️ 风险…
【⏳ 未实测的部分】哪些没验，怎么验
【要你拍板的】具体是哪一条
```

---

## 1. 语言选型

**什么时候用**：新项目开工、要加一门新语言、要把某个模块换语言。

| 维度（权重） | 要查什么 |
|---|---|
| ⭐ 使用环境（高） | 目标机器（Windows/mac/Linux）、要不要装运行时、用户会不会用命令行 |
| ⭐ 开发环境（高） | 你熟不熟、调试器好不好用、生态库够不够 |
| 性能（中） | 是"够用"还是"是瓶颈"？（⛔ 别过早优化） |
| 部署形态（中） | 单体 exe / 需要运行时 / 需要服务 |
| 生态与维护（中） | 库多不多、社区活不活跃、招人好不好招（个人开发可忽略） |
| ⛔ 反面 | 它**做不到什么**（如脚本语言做不了低延迟渲染） |

**⚠️ 常见误判**：拿"语言性能"给一个**根本不受性能限制**的项目做决定。

## 2. 架构选型

| 维度 | 要查什么 |
|---|---|
| ⭐ 规模（高） | 现在几个模块？一年后可能几个？ |
| ⭐ 变更频率（高） | 哪部分天天改（要隔离）、哪部分冻死（要保护） |
| 几个人做（高） | **个人开发 ⇒ 层数越少越好**，⛔ 别照抄大厂分层 |
| 部署与调试（中） | 能不能单机跑、出错好不好定位 |
| ⛔ 反面 | 它**带来什么新麻烦**（如事件驱动难调试、微服务要运维） |

**⚠️ 常见误判**：为"以后可能变大"提前上重架构（个人开发的头号杀手）。

## 3. 依赖 / 库选型 ⭐

| 维度 | 要查什么 |
|---|---|
| ⭐⭐ 许可证（高） | **GPL 有传染性！** MIT/Apache 安全；⛔ GPL 别链接进主程序 |
| 体积（中） | 包多大 |
| ⭐ 传递依赖数（中） | 拉进来多少个间接包（越多越危险） |
| 活跃度（中） | 最后更新时间、issue 有没有人回 |
| 精度/功能匹配（高） | 它到底能不能干这活（要**实测**） |
| ⛔ 反面 | 它**不支持什么**（例：某 DXF 库不支持动态块） |

**⚠️ 常见误判**：只看星数不看许可证；只看文档说支持、没实测。

## 4. 模型选型（LLM / 视觉）

| 维度 | 要查什么 |
|---|---|
| ⭐ 单价（高） | 按 token / 按张 |
| 上下文长度（中） | 够不够塞下你的提示词 |
| 中文能力（高） | 中文场景必须实测 |
| ⭐ 结构控制能力（高） | 支不支持**参考图 / 线稿 / 构图约束**（决定能不能保结构） |
| 延迟（中） | 单次几秒（影响体验） |
| ⛔ 反面 | 它**会不会改结构**、会不会胡编 |

**⚠️ 常见误判**：拿"通用能力排名"选一个**保不住结构**的模型去出工程图。

## 5. 可行性预判 ⭐

**输出必须是这个形状**：
```
【能不能做】能 / 不能 / 有条件能
【依据】⭐ 必须带实测证据（我跑过什么 / 谁验证过 / 文件:行号）
【已知的坑】至少 2 条
【⏳ 未实测】哪些没验
```
⛔ **不许凭直觉说"能"或"不能"**（A5）。

## 6. 风险清单

**来源**：⛔ 不许编。只能来自 `教训表.md` ＋ 本项目已发生的坑。
**输出**：`风险 / 触发条件 / 后果 / 现在能做什么`.

## 7. 规模判断（工期）

| 维度 | 要查什么 |
|---|---|
| 参考同类（高） | **找做过的东西的实测耗时**（⛔ 不许拍脑袋） |
| 未知数（高） | 有几个"没做过、不知道要多久"的部分（×2 缓冲） |
| ⛔ 反面 | 最容易低估的是哪块 |

**输出**：`最乐观 / 最可能 / 最坏` 三档 ＋ 建议**先做最小版**。

## 8. 数据 / 格式选型 ⭐

| 维度 | 要查什么 |
|---|---|
| ⭐ 开放性（高） | 是开放格式还是专有格式（专有＝被绑定） |
| ⭐ 免费库许可（高） | 见第 3 项（GPL 传染） |
| 精度（高） | 会不会丢信息（要实测：**同一份数据转一圈再比**） |
| 生态（中） | 有多少工具能读 |
| ⛔ 反面 | 转换会**丢什么**（例：某方案会丢动态块/图层信息） |

**⚠️ 铁律**：⭐ **"转一圈再比"是唯一可信的验证法**（转出去、转回来、逐项对）。

## 9. 资料精读（图 / 视频 / 长文档）⭐

**必须输出的三样**：
```
① ⭐ 抽取密度：时长 ÷ 实际读数（视频 ≤1 帧/秒；加速视频按内容帧算）
② ⭐ 索引表：位置/时间戳 → 内容（一行一条）
③ 结论：每条带出处（文件名:秒数 / 文件:行号）
```
**⚠️ 铁律**：⛔ 密度不够就**补抽**，不许先下结论（F1/F2）。
**⚠️ 常见误判**：抽帧位置裁错（裁到 UI 控件）⇒ **必须先扫一遍定位**。

## 10. 外部调研 ⭐

**必须查三层**（F4）：
```
① 表面功能（宣传页说了什么）
② ⭐ 实现方式 / 技术栈（怎么做的、依赖什么）
③ ⭐ 许可证 / 体积 / 依赖数 / 最后更新
```
**必须找反面对照**（F5）：至少一条"做不到 / 会翻车"的证据。
**⚠️ 铁律**：⛔ **厂商通稿不算事实**（A2）。查不到 ⇒ `⏳ 未实测`。

## 11. 方案对比

**必须并排**（⛔ 不许只给一个方案）：
```
方案 A：做法 / 成本 / 风险 / 何时选它
方案 B：…
方案 C：…
⇒ 推荐：X（理由）｜ 什么情况下改推 Y
```

## 12. 成本预算 ⭐

| 项 | 怎么算 |
|---|---|
| API/云费 | 单价 × 预计次数 × 试错倍数（**试错通常 3~5 倍**） |
| 硬件 | 要不要换机器/显卡 |
| 时间 | 照第 7 项 |
| 维护 | 以后每月要花多少精力 |

⛔ **不经人同意不许花钱**（E2 / Q2）。

## 13. 硬件选型 ⭐

| 维度 | 要查什么 |
|---|---|
| 用途匹配（高） | 是 CPU 密集还是 GPU 密集 |
| ⭐ 现有设备够不够（高） | **先测现有机器**，⛔ 别急着买 |
| 显存/内存（高） | 决定能不能跑（如 6GB 显存能跑什么） |
| 功耗/噪音/散热（中） | 个人开发环境要能长期开机 |
| ⛔ 反面 | 买了也跑不动的情况 |

**⚠️ 铁律**：⭐ **先跑一遍实测（谁在占资源、瓶颈在哪）再谈升级**。

## 14. 渲染 / 出图方案选型

| 维度 | 要查什么 |
|---|---|
| ⭐ 保结构能力（高） | 出图后**几何/尺寸有没有被改**（要实测比对） |
| 质量（高） | 目视 ＋ 可度量指标 |
| 速度（中） | 单张几秒~几分钟 |
| 成本（高） | 按张计费 / 本地免费 |
| ⛔ 反面 | 哪种角度/场景它做不好 |

⭐ **必须做的实测**：**同一输入出 N 张，比对结构是否漂移**。

## 15. 测试策略

| 问题 | 要求 |
|---|---|
| 什么算通过？ | ⭐ **事前写清判据**（⛔ 不许"看起来对"） |
| 怎么复现？ | 一条命令能重跑 |
| 谁验证的？ | 真人/真输出，⛔ 不许 AI 自证 |
| 失败了怎么办？ | 回滚（J2） |

⭐ **优先做**：**"一句话体检"式的机械检查**（B1），而不是人工点一遍。

## 16. 发布与分发

| 维度 | 要查什么 |
|---|---|
| 形态（高） | 单文件 / 安装包 / 需要运行时 |
| ⭐ 依赖打包（高） | 目标机器要不要装别的东西 |
| 升级方式（中） | 怎么给人新版本、怎么回退 |
| 授权/许可（高） | 自己代码和第三方库的许可 |
| ⛔ 反面 | 别人机器上跑不起来的常见原因 |

## 附：16 项的共同纪律（⛔ 违反任何一条，结论作废）

```
① 只给「选项 + 后果 + 推荐」，⛔ 不替人拍板（E1）
② 每条结论带出处；查不到标「⏳ 未实测」+ 怎么验（A1 / B3 / F6）
③ 以实测为主，⛔ 厂商口径和印象不算证据（A2 / L3）
④ 选型必须给横评表，维度含【使用环境】【开发环境】（L1 / L2）
⑤ 每个选项至少一条反面（L4）
⑥ 结论落「已定事项表.md」，⛔ 定了不许再漂（L5 / G1）
```

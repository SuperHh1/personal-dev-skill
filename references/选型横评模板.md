# 选型横评模板（照抄即用）

> 适用：**语言 / 架构 / 依赖库 / 模型 / 数据格式 / 硬件 / 渲染方案 / 测试策略 / 发布方式** 等一切"要选一个"的场合。
> ⛔ **不许跳模板直接给结论**（`SKILL.md` L1）。
> ⭐ **AI 只填表 ＋ 给推荐；拍板的是人**（E1）。

---

## 一、表头（先填这五行）

```
选型主题：<要选什么>
日期：<YYYY-MM-DD>
决策人：<人>            ← ⛔ 永远是人，不是 AI
本次要紧程度：<高/中/低>  ← 决定花多少时间
复选频率：<一次性 / 会再评估>
```

## 二、横评表（⭐ 核心）

| 维度 | 权重 | 选项 A | 选项 B | 选项 C |
|---|---|---|---|---|
| ⭐ **使用环境**（目标机器/用户习惯/部署） | 高 | | | |
| ⭐ **开发环境**（语言/工具链/调试/熟悉度） | 高 | | | |
| ⭐ **许可证**（传染性？商用？署名？） | 高 | | | |
| 体积 | 中 | | | |
| ⭐ 传递依赖数 | 中 | | | |
| 维护活跃度（最后更新 / issue） | 中 | | | |
| 学习成本 | 中 | | | |
| 性能 | 中 | | | |
| 成本（钱 / 时间 / 精力） | 高 | | | |
| ⛔ **它做不到什么**（→ 每项至少填一条） | — | | | |
| ⭐ **实测证据**（我跑过什么 / 文件:行号 / URL） | — | | | |
| ⏳ **未实测的部分** | — | | | |

> ⭐ **打分建议**：`✅ 好 / ⚠️ 可以接受 / ⛔ 不行`，或者 `1~5`。
> ⛔ **不许只填"好/不错"这种没法比较的词。**

## 三、结论（照这个写）

```
【推荐】选项 X
【理由】……
【⚠️ 风险】选它以后要接受什么
【什么情况下改推 Y】……
【⏳ 未实测的部分】…… 怎么验：……
【要你拍板的】确认用 X 吗？
```

## 四、⛔ 五条硬规矩

```
① 维度里【使用环境】【开发环境】不许省 —— 少了这两行，结论就是空的（L2）
② 每个选项至少一条反面（L4）
③ ⛔ 厂商宣传口径和"我觉得"不算证据（A2 / L3）
④ 实测不了 ⇒ 标「⏳ 未实测」+ 怎么验（B3）
⑤ 定完了 ⇒ 立刻写进 `已定事项表.md`，⛔ 以后不许再漂（L5 / G1）
```

## 五、示例（已填好，只作格式参考）

```
选型主题：DXF 解析库
日期：2026-10-02       决策人：用户       本次要紧程度：高

| 维度 | 权重 | netDxf | 自研解析 | 商业库 |
|---|---|---|---|---|
| ⭐ 使用环境 | 高 | ✅ .NET 原生 | ✅ 完全可控 | ⚠️ 要授权 |
| ⭐ 开发环境 | 高 | ✅ C# 直接用 | ⛔ 工作量大 | ⚠️ 要学 SDK |
| ⭐ 许可证 | 高 | ✅ MIT | ✅ 自有 | ⛔ 商用收费 |
| ⭐ 传递依赖数 | 中 | ✅ 少 | ✅ 零 | ⚠️ 未知 |
| 维护活跃度 | 中 | ⚠️ 一般 | — | ✅ 有厂商 |
| ⛔ 它做不到什么 | — | **不支持动态块** / 没有可见性 API | 全部要自己写 | 绑定厂商 |
| ⭐ 实测证据 | — | 反射验证：只有 Block/BlockRecord，无动态块类型 | — | ⏳ 未实测 |

【推荐】netDxf ＋ 自己补洞（动态块那部分用反射读原始 DXF）
【⚠️ 风险】升级库时要重新验证反射代码
【⏳ 未实测】商业库到底支不支持动态块 —— 验法：问厂商要试用版跑一遍
```

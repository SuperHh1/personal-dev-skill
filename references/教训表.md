> ⭐ **这是本技能包最值钱的部分** —— 规则不是抄来的，是**踩出来的**。

## 已入库（真实案例，可直接引用）

### 教训 1 · 把"文档里有"当成"功能已经做了"
- **我做了什么**：看到有接口 ＋ 三个按钮，就说"彩平/轴测能力在"。
- **真相**：按钮自己弹窗写"还不能直接出图"；`LocalEngine` 全工程 **0 个构造点**。
- **根因**：把文档/骨架当事实。
- **对应守则**：**A1 / A3**
- **以后怎么防**：说"有"之前必须 `grep` 到构造点或自检断言；找不到就说"只有占位"。

### 教训 2 · 把"白名单注释"当成"零消费者"
- **我做了什么**：凭注释断言某接口没人调用。
- **真相**：**已有 3 处真实调用**。
- **根因**：注释 ≠ 事实。
- **对应守则**：**A1**
- **以后怎么防**：查调用必须全局搜索符号名，⛔ 不看注释。

### 教训 3 · 拿厂商宣传口径当技术事实（一）
- **我做了什么**：把"自研渲染引擎 / 自研几何内核 / 多模态 CAD 大模型"当事实写进文档。
- **真相**：**纯营销口径**（用户原话：「又不是没用过他们的东西，就是一坨」）。
- **根因**：把宣传当证据。
- **对应守则**：**A2 / F4 / F5**
- **以后怎么防**：厂商说法一律标"**厂商自述·未经独立验证**"；必须去找反面。

### 教训 4 · 拿厂商宣传口径当技术事实（二）⭐
- **我做了什么**：照抄"NVIDIA DLSS 5 = RTX 50 独占"，判"你用不了"。
- **真相**：**GitHub 上开源项目让 10 系卡也能用**：
  `DLSS5-Swapper`（7489⭐/MIT）、`DLSS-Enabler`（1369⭐/MIT，原话"on **any** DirectX 12 compatible GPU"）、
  `OptiScaler`（11512⭐）。实测视频里榜单从 RTX 5090 一路排到 **GTX 970 / GTX 1050 / GTX 1060 5GB**。
- **根因**：**只查了一层（官方通稿），没查实现方式**。
- **对应守则**：**A2 / F4 / F5 / L3**
- **以后怎么防**：调研必须查三层（功能/实现/许可证），且**必须去 GitHub 搜一遍**。

### 教训 5 · 挑几条样本就下结论 ⭐
- **我做了什么**：62 帧的视频只看 6 帧，就写"结论"。
- **真相**：用户原话「**我感觉你都没仔细看我给你的东西**」；逐帧读完才发现关键信息（"线稿上色""保持结构不动""画布助手""尺寸精确"全漏了）。
- **根因**：**省 token 省到了不该省的地方**。
- **对应守则**：**F1 / F2 / H（总原则）**
- **以后怎么防**：⭐ 先算**抽取密度**（时长÷读数）；低于阈值**必须补抽**。

### 教训 6 · 用"逻辑推理"替代实测
- **我做了什么**：推理"DLSS 要引擎集成 ⇒ 进不了我们的链"，没跑任何验证就当代结论。
- **真相**：⛔ 推理不是证据；而且我连"引擎集成"这个前提都没实测。
- **根因**：把自洽当成正确。
- **对应守则**：**A5 / A7**
- **以后怎么防**：推理只能当**假设**；结论必须带实测或标 `⏳ 未实测`。

### 教训 7 · 抽帧位置裁错，还以为读到了
- **我做了什么**：用同一个裁切带套所有视频，结果裁到 UI 控件/黑边，**字幕根本没进画面**，我却继续"分析"。
- **真相**：各视频字幕位置不同（v1 在 y≈1120、v2 在 y≈700、v3 在 y≈550）。
- **根因**：**没先验证"我到底看到了什么"**。
- **对应守则**：**F1 / C4**
- **以后怎么防**：⭐ 抽帧前先做一张**位置扫描图**，确认字幕/内容在画面里。

### 教训 8 · 改动引入的回归，靠推理而非基线
- **我做了什么**：断言某改动"会导致原来命中"，没跑旧版。
- **真相**：自检 `68/0 → 67/1` 才暴露问题；新增判据放错位置成了**死代码**。
- **根因**：没拿基线。
- **对应守则**：**A7 / A8 / B4**
- **以后怎么防**：⭐ 改判据/加分支**之前**跑一次旧版，**记录数字**。

### 教训 9 · 后台线程建定时器，服务集体哑掉
- **我做了什么**：在 `Task.Run` 里建 `DispatcherTimer`/窗口。
- **真相**：**永不触发、还不报错**；四个服务一起哑，症状是面板写"她看到你：没看到"。
- **根因**：UI 对象必须建在 UI 线程。
- **对应守则**：**D1 / C3**
- **以后怎么防**：UI 定时器/窗口一律建在 UI 线程；且**失败不许静默**。

### 教训 10 · `catch { }` 吞异常，多花好几轮找真因
- **我做了什么**：异常被空 catch 吞掉。
- **真相**：真因是 `Topmost=true` 的窗口不许挂 `Owner`，赋值抛了被吞了。
- **根因**：静默失败。
- **对应守则**：**C3 / J3**
- **以后怎么防**：⛔ 禁止空 catch；异常必须带时间戳落日志。

### 教训 11 · 中文路径把脚本/工具链搞崩
- **我做了什么**：用中文路径跑命令行批处理。
- **真相**：路径变成 `工程目录\???????\`（脚本存成了 ASCII）；编码 GBK/UTF-8 打架。
- **根因**：工具链对中文路径和编码的假设。
- **对应守则**：**D2 / K2 / K3**
- **以后怎么防**：脚本文件存 ascii；路径禁中文/空格/全角；或先拷到 ASCII 临时路径再跑。

### 教训 12 · 宿主语言字符串里的嵌套转义引号
- **我做了什么**：在字符串里用转义引号写中文。
- **真相**：**反复编译错误**（CS1009/CS1003 等），来回好几轮。
- **根因**：转义是高频事故源。
- **对应守则**：**D4**
- **以后怎么防**：⭐ 字符串里优先用**全角引号「」**，⛔ 少用转义。

### 教训 13 · 忘了已经敲定的事，又按旧思路想

### 教训 14 · 用户纠正过的名词，我又猜错

### 教训 15 · 说"全读完了"其实没读完

### 教训 16 · 写出来的脚本自己就踩了"编码坑"⭐
- **我做了什么**：用工具生成 `.ps1` 脚本（内含中文），没检查文件编码。
- **真相**：文件存成了**无 BOM 的 UTF-8**，PowerShell 5.1 按 GBK 读 ⇒
  **13 个语法错误**，报错里全是乱码（「浠撳簱」＝「仓库」）；带 BOM 重存后 **0 错误**。
- **根因**：**写代码的人（我）没把守则 D2/D3 用在自己身上** ——
  刚写完"编码坑"那一条，转头就踩。
- **对应守则**：**D2 / D3 / C4 / K3**
- **以后怎么防**：⭐ **凡生成含非 ASCII 的脚本文件，一律存 UTF-8 带 BOM**；
  并且⭐⭐ **交付前必须做一次"只解析不执行"的语法检查**（机械动作，⛔ 不靠看）：
  ```
  $e=$null;$t=$null
  [System.Management.Automation.Language.Parser]::ParseFile($path,[ref]$t,[ref]$e)
  $e.Count   # 必须是 0
  ```
- **补充（同一天第 2 次犯）**：用 `edit` 工具改脚本后 **BOM 又被剥掉了**（12 个错误）。
  ⇒ ⭐ 规矩升级：**`write` / `edit` 之后，都必须重新确认 BOM ＋ 跑一次语法复检**。

### 教训 20 · ⭐ 全局 git 里的"代理改写"能让 push 彻底坏掉 ⭐⭐
- **日期**：2026-10-03
- **我做了什么**：直接用 `git push` 推一个新仓库，连试 3 次都失败。
- **真相**：用户的全局 `.gitconfig` 里有一条
  ```
  [url "https://gh-proxy.com/https://github.com/"]
      insteadOf = https://github.com/
  ```
  ⇒ 它把**每一个** `https://github.com/...` 都改写成 `https://gh-proxy.com/https://github.com/...`
  - 后果①：push 报 `404`（代理上当然没有你的新仓库）
  - 后果②：**把带认证的 URL 拼坏** —— 变成
    `gh-proxy.com/https://github.com/https://用户:token@github.com/...` ⇒ 直接不可用
  - 后果③：我在仓库级想"反向覆盖"它，结果**把它自己改坏了**（反而删掉了用户名）
- **根因**：⭐ **`insteadOf` 是全局生效的字符串改写，仓库级配置很难局部覆盖它**，
  而且它跟"代理能不能用"是两件事 ——
  ⚠️ 实测 `gh-proxy` 本身 **HEAD 返回 200（代理是活的）**，它只是**不支持 git push**。
- **对应守则**：**D2 / K2 / C4**
- **以后怎么防**：
  ⭐⭐ **遇到 push 失败，先看 `.gitconfig` / `git config --get-regexp 'url\.'`**，
  ⛔ 别一股脑怀疑网络。
  ⭐ **更稳的做法：改用 GitHub API 逐文件上传**（见教训 21），完全不经过 git ⇒
  任何 URL 改写都影响不到它。这条已落进上传脚本。

### 教训 21 · ⭐⭐ 网络不稳时，"一次大推送"必输，"逐文件小请求"能赢
- **日期**：2026-10-03
- **我做了什么**：先试 `git push`（一次要把整个仓库推上去）。
- **真相**：这台机器连 GitHub **很不稳**：
  - `git ls-remote` 3 次里 1 次超时、1 次成功、push 时 `Connection was reset`
  - 而同一条网络下，**PowerShell 走 GitHub API 的 16 个小 PUT 请求全部成功（16/16）**
  - 另有证据：`Invoke-WebRequest https://github.com/用户/仓库` 直接超时，但 `api.github.com` 通
- **根因**：⭐ **一次大传输必须从头成功到尾**；任何一次抖动就整单失败。
  小请求各自独立重试 ⇒ 单点抖动只影响那一个文件。
- **对应守则**：**R1 / C5 / L6（换个更稳的路，⛔ 不在坏路上硬顶）**
- **以后怎么防**：
  ⭐ 传输类任务（上传/下载/推送）**优先拆成小请求 ＋ 每个请求独立重试**；
  ⛔ 不要"失败就再试同一个大动作" —— 那是浪费时间。
  ⭐ 判据：**失败率随"单次传输量"上升 ⇒ 就该拆小**。

### 教训 23 · ⭐⭐ "联动"要改的是【状态】，⛔ 不是只改一个局部变量
- **日期**：2026-10-04
- **我做了什么**：做"层高↔墙高联动"（照酷家乐规则）时，
  规则②是「墙高 ＞ 层高 ⇒ **层高及所有墙高**同步更新」。
  我第一版只把局部变量 `tall` 改了，**没重建 `storey` 那个状态对象**。
- **真相**：⭐ **实测抓到了** —— 用 `--echo-walls` 把每条墙的高打出来：
